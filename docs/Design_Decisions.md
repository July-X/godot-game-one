# 设计决策

本文档冻结当前项目的方向。如果以下任何决策发生变化，请先更新此文件，然后更新实现和相关参考文档。

## 1. 游戏定位

- **2D 俯视角 Roguelike 弹幕射击游戏**（项目名 `Space Bullet Hell`）。
- 引擎 Godot 4.6 + GDScript，2D 渲染，设计视口 1280×720。
- 基调：星际空战，高对比街机可读性，街机式短循环。
- 美术与音频**全部程序化生成**，不依赖外部资源；仅 Boss / 玩家等级外形使用仓库 AI 产出的 PNG。
- 单局无固定时长，由升级曲线与死亡结束；目标是「随时能开一局、随时能弃一局」。

> 历史说明：2026-05 之前本项目曾是「单机 3D 微剧情动作游戏」的垂直切片，
> 该版本已整体废弃并归档在 `backup_3d/`，不再作为设计依据。

## 2. 范围冻结

- 单局内必须有明确的开始和结束，不做开放世界。
- 不引入互联网服务器、云后端、matchmaking、账号系统。
- 不做大型技能树；成长只走「三属性 + 护盾 + Boss 持久强化」五条线。
- **2 人本地联机合作是允许的**（见 §13），但只是对单机流程的叠加，不改变核心循环。

## 3. 核心循环

1. 鼠标惯性移动，自动射击。
2. 击杀敌人累积积分与等级（`10 + level*5` 击杀升一级）。
3. 每 20 击杀触发精英战（护盾四阶段）。
4. 每 5 级触发 Boss 战（三阶段 + 终局究极激光炮）。
5. 拾取掉落物强化扩散 / 速射 / 威力，或回复、炸弹。
6. Boss 死亡由 Host 权威发放持久强化。
7. 死亡进入结算。

## 4. 相机和操作

- 固定俯视 2D 相机，无自由旋转或跟随偏移。
- 移动：鼠标相对位移累积成速度并按帧衰减，形成惯性手感；移动端走左侧虚拟摇杆。
- 射击：全自动，玩家只负责走位；这是弹幕射击的核心操作契约。
- 技能：环形散射（15s）与激光（10s）两个主动技能，作为 build 差异化的主要来源。

## 5. 视觉方向

- 2D 精灵 + 高对比饱和前景 / 克制背景。
- 低分辨率程序化像素贴图，默认最近邻过滤，保持街机质感。
- 可读性优先于真实感：弹幕、玩家、精英、Boss 必须一眼分得开。
- 额外细节服务于战斗清晰度，不允许遮挡弹幕。

## 6. 音频方向

- 短促有力的武器和受击音效。
- 清晰的伤害、死亡、拾取和 UI 确认反馈。
- 循环 BGM 支持长时间连续游玩；Boss 阶段需有独立的压迫感变体。

## 7. 当前生产顺序

1. 保持联机链路（Harmony 发现 + ENet 战斗）稳定，不引入新的传输方案。
2. 补齐精英 / Boss 战斗节奏与手感。
3. 打磨双机同步性能，保证加入端帧率。
4. 扩充关卡节奏与敌人构成。
5. 最后才做外部美术资产替换。

## 13. 多人合作模式设计决策（2026-05-09）

### 范围变更确认
- **原禁止事项已解除**：正式引入 2 人本地近距离联机合作模式。
- 不引入互联网服务器、不引入云后端、不引入 matchmaking。
- 仍保持"短流程完成"定位，多人模式是对原单机流程的叠加，不改变核心玩法循环。

### 通讯方案决策：Wi-Fi 热点 LAN + ENet
- **选用原因**：Godot 4 原生 `ENetMultiplayerPeer` 支持，无需插件，Android 无需额外权限（INTERNET 已涵盖）。
- **蓝牙/星闪放弃原因**：Godot 4 无内置蓝牙 API；星闪（NearLink）为华为封闭生态，无第三方 SDK；两者集成均需原生插件，开发成本过高。
- **连接方式**：一台手机开 Wi-Fi 热点作为 Host（服务器，peer_id=1），另一台连接热点作为 Client。Client 输入 Host IP（通常 `192.168.43.1`），无需互联网。
- **延迟预期**：局域网内 < 10ms，完全满足动作游戏需求。

### 权威模型
- **服务器权威**：Host（peer_id=1）拥有所有敌人、Boss、弹幕的生命周期控制权。
- **玩家自主权**：每个玩家节点的 `multiplayer_authority` 设置为其 peer_id，玩家本地直接控制移动，通过 MultiplayerSynchronizer 同步位置给对方。
- **GameState 同步**：Score、Level、Health 由服务器 RPC 广播，客户端只读。
- **联机死亡判定**：P1/P2 任意一方死亡只从存活列表移除并切换敌人目标；只有 P1/P2 全灭才触发 Game Over。房主 P1 死亡不能触发断网回退或切换单机。
- **联机 UI 命名**：记分牌、实时排行榜和历史排行榜统一使用 `P1/P2`，不再使用 A/B。

### 多人玩法设计
- **模式**：2 人合作，共同击杀敌人，共享积分和进度，各自独立血量。
- **大厅流程**：标题画面 → 选择 Host/Join → 大厅等待 → Host 按"开始" → 游戏场景。
- **断线处理**：任意一方断线，当前场景先清理网络实体、同步缓存与对象池，再断开网络并异步进入新的单人主场景，保留玩家继续游玩的机会，不再停在半同步状态或继承联机性能负载；模式切换提示固定停留 5 秒，避免玩家错过切换原因。
- **平台**：纯 Android 双端，iOS 暂不考虑。
- **配置降本策略**：Host 面板提供固定推荐热点名 `SpaceBattle_Game`、固定推荐密码 `BATTLE66` 与“一键复制”按钮，减少用户在系统设置中的输入成本，提升联机发起意愿。

### 技术架构
- `NetworkManager`（Autoload）：管理 ENet 连接，发出 `player_connected` / `player_disconnected` / `server_disconnected` 信号。
- `主机 RPC 复位`：进入 `main.tscn` 后由 Host 显式向所有 Client 广播玩家生成状态，客户端先请求一次完整同步，避免错过早期生成消息。
- `MultiplayerSynchronizer`：每个 Player 节点子节点，同步 `position`、`rotation`（ON_CHANGE 模式）。
- 敌人生成、伤害判定、Boss 逻辑均在服务器端执行，通过 RPC 广播与 Synchronizer 同步到 Client。
- 敌人、Boss 与子弹的视觉副本仍走 RPC 广播，不依赖自动场景复制。

### 鸿蒙万物互联迁移决策（2026-05-09）

- **迁移目标**：降低“手动开热点 + 手动进设置”的用户操作成本，在华为鸿蒙设备优先提供“附近发现直连”体验。
- **迁移边界（M1）**：
  - 仅替换“大厅发现/配对入口”，战斗期实时同步仍沿用 Godot ENet。
  - 即：Harmony 用于发现与传递连接参数，ENet 用于实时对战数据。
- **架构策略**：
  - 新增 `HarmonyBridge`（Autoload）作为插件适配层，不让大厅脚本直接依赖原生 API。
  - `NetworkManager` 新增 `transport_mode`（`enet` / `harmony`）标记，用于记录当前会话来源。
  - `Lobby` 入口策略：大厅发现与配对统一走 `HarmonyBridge`；插件不可用时由桥接层内部回退调试后端。
- **回退保证**：
  - 任何 Harmony 插件缺失/方法缺失/调用失败，都通过 `HarmonyBridge` 回退到调试后端，保证开发可验证。
- **后续里程碑（M2/M3）**：
  - M2：完成原生插件（ArkTS/Java）与 `HarmonyBridge` 契约对齐，打通真机发现回调。
  - M3：评估是否将战斗期传输也迁移到 Harmony 会话通道（仅在延迟/稳定性达到 ENet 基线时推进）。

### 迁移完成定义（Godot 侧）

- 已完成项（本仓库）：
  - 联机大厅默认流程已切换为 Harmony 附近发现。
  - 热点/手动 Wi-Fi 按钮不再作为主流程，仅保留调试回退。
  - `HarmonyBridge` 统一承接插件检测、发布、扫描、回调上报。
  - 已提供插件契约文档：`docs/Harmony_Plugin_Contract.md`。
- 待外部实现项（仓库外原生插件）：
  - HarmonyOS 实机互联后端能力替换/增强（当前仓库骨架后端为 Android NSD）。
  - 双端鸿蒙真机联调与稳定性压测。

### 迁移实施细节补充（2026-05-09 晚）

- **房间命名规则**：发布名采用 `基础名-设备短标识`（均截短）以降低同名冲突；并对 `null/(null)` 做发布前清洗。
- **加入防崩规则**：大厅仅允许 IPv4 地址进入 ENet 连接流程；解析到非 IPv4 地址时直接在大厅提示，不发起连接。
- **调用时序规则**：点击“加入”后通过 deferred 调用发起连接，避免 UI 输入回调栈直接承载网络调用导致崩溃扩散。

## 10. Boss 战手感规则（2026-05-08）

- Boss 受击有“明显反馈”但不允许被连续子弹推离战场。
- 击退属于视觉反馈层，不应主导 Boss 的战略位移；Boss 的主要位移应来自状态机（机动/撤退/冲刺）。
- 对高频命中启用击退衰减：短时间内连续命中时，后续击退距离递减，避免“无限后退”。
- Boss 运动强制限定在可视战场边界内，避免脱离屏幕后造成战斗中断或可读性下降。

## 11. 外形演进规则（2026-05-08）

- Boss 使用 5 张外形变体图（`boss_01`~`boss_05`），每次出场轮换且避免连续重复同一张。
- 玩家飞机外形按角色等级分档：每 5 级切换一次外形，最多 5 档（`lv01`~`lv05`）。
- 玩家等级提升后，若跨越分档阈值（5/10/15/20 级），本局立即更新飞机外形。

## 12. Boss 战阶段规则（2026-05-08）

- Boss 战是独立波次：Boss 出场时立即清空场上常规敌人、掉落物、小行星与弹幕，避免干扰 Boss 手感。
- Boss 战视觉和音乐与常规战斗分离：进入 Boss 阶段时启用独立背景色与更高压迫感的 BGM，Boss 死亡后恢复。
- Boss 血量按玩家当前 DPS 动态估算（`BOSS_TARGET_TTK_SECONDS = 42.0`，即目标约 42 秒击杀），避免"瞬秒"或"过长拖战"。
- Boss 机动性优先于被击退：近身时触发脱离，保持中距离压制，不允许被贴脸连击持续压在同一位置。
- Boss 精灵显示尺寸与碰撞体必须保持一致（约原生成尺寸的 2/3），保证视觉大小与命中体积不脱节。
- Boss AI 使用预测瞄准、侧向巡航、假动作偏移和中距离压制；攻击弹幕降低单发秒杀风险，强调可躲避的压迫感。
- Boss 血量必须通过实体同步接口广播到加入端，客户端幽灵副本只显示服务器血量，不自行结算。
- 玩家初始生命为 50 点，治疗仍可在满血时转化为生命上限成长，上限保持 2000。

## 14. 精英/Boss 重设计落地约束（2026-05-11）

- 精英怪固定采用四阶段结构：护盾压制（A）→ 破盾暴露（B）→ 裂隙召唤（C）→ 濒死掠夺（D）。
- 破盾暴露窗口固定 4 秒，窗口内精英承伤系数为 1.25，用于鼓励技能集火。
- 精英死亡固定掉落 12 个道具；联机模式下按存活玩家轮转分配归属，归属仅影响优先吸附。
- 掉落物磁吸手感统一为加速度曲线（320→720，0.35 秒），精英/Boss 掉落归属信息必须随实体同步到加入端。
- 精英/Boss 战斗提示统一走 HUD 横幅，不再分散在场景临时 Label 逻辑中。
- Boss 固定采用三阶段：压制校准（100%-70%）、裂隙展开（70%-35%）、核心过载（35%-0%）。阶段由 Host 血量权威决定，Client 只根据同步血量显示阶段。
- Boss 终局技「究极激光炮」按**血量台阶**触发，不是只在 10% 触发一次：每损失 25 个百分点血量（`BOSS_ULTIMATE_LASER_HP_INTERVAL = 0.25`）就触发一次。完整时序为 **2 秒蓄力 → 3 秒尖端推进 → 10 秒持续束**，束宽 110px。内圈（束宽的 30% 以内）直接秒杀，外圈按 10 HP/s 累积伤害。推进阶段只检测光束**当前尖端到起点**的范围，玩家可以跑出推进路径躲避。联机下只由 Host 触发和结算，Client 只显示同步视觉。
- Boss 目标击杀时长从约 20 秒调整为约 42 秒，避免阶段改造后仍被高成长火力快速跳过。
- Boss 召唤无人机上限为 2；裂隙门使用短生命周期轻量绘制节点，不常驻场景，避免加入端和低端机承担额外 AI/节点成本。
- Boss 核心碎片必须按拾取者显示短提示；Boss 死亡后的持久 Buff 不再弹选择面板，必须由 Host 按获得者 peer 随机发放并追加到左侧子弹属性条下方的 Boss 强化分组，使用与扩散/速射/威力一致的进度条样式；联机下奖励只由 Host 按 peer_id 写入 `GameState`，Client 不能本地自结算。
- 玩家导弹和激光技能优先锁定 Boss 与精英怪；只有不存在高威胁单位时才回退普通敌人。
- 玩家护盾按层吸收伤害，有护盾时任何正数伤害至少消耗 1 层，避免小数弹幕绕过护盾反馈。
- 精英护盾视觉只允许使用 `shield_circle.gd` 的圆形绘制光晕和顶部护盾条；旧 `ShieldSprite` 方形渐变纹理不得在战斗中重新显示。
- 精英护盾破裂必须有可见的圆形碎裂/炸裂效果，不能只隐藏光晕。
- 联机实体主同步包只承载 `entity_id/position/health` 基础字段，并使用 `PackedFloat32Array`；护盾、Boss 朝向等少数实体专有状态必须拆成小型独立同步包，避免双屏战斗时所有实体承担无效字段带来的卡顿。
- 联机小行星销毁必须同时从 `_entities`、目标插值缓存、场景节点和 `asteroids` 分组兜底清理；兜底清理必须支持 `entity_id`，不能只依赖节点名。
- Client 如果在主同步包中收到未知 `entity_id`，必须限频请求 Host 重发当前实体快照，作为可靠 spawn RPC 偶发漏收后的自愈路径。
- 移动端技能按钮必须使用设计视口右下锚点布局；项目采用 `window/stretch/mode="viewport"`，不要用 Android 物理窗口尺寸直接计算 HUD 坐标，否则会在导出包中把按钮放到 1280x720 设计画布外。
- `HUD` 继承 `CanvasLayer`，不能直接调用 `get_viewport_rect()`；需要视口尺寸时使用项目设计视口尺寸或 `get_viewport().get_visible_rect()`。HUD/主场景问题必须跑主场景运行验证，单纯 `--quit` 不能覆盖脚本解析和 `_ready/_process` 链路。
