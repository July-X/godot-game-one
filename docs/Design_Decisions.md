# 设计决策

本文档冻结当前项目的方向。如果以下任何决策发生变化，请先更新此文件，然后更新实现和相关参考文档。

## 1. 游戏定位

- 单机 3D 微剧情游戏。
- 目标时长：1 小时以内。
- 基调：紧凑的科幻救援任务，带有轻度叙事框架。
- 风格参考：NES / Contra 风格，但用 3D 重建，具有现代可读性。

## 2. 范围冻结

- 先构建完整的垂直切片，再扩展内容。
- 无多人、无在线服务、无后端依赖。
- 无大型开放世界。
- 暂无大型技能树或系统化成长层。
- 专注于一个短小、可重玩的动作循环，具有明确的开始和结束。

## 3. 核心循环

1. 简报和目标设定。
2. 通过一条充满敌意的走廊或紧凑竞技场移动。
3. 与一小群敌人战斗。
4. 到达终端、开关或出口条件。
5. 解决剧情节点并结束本轮。

## 4. 相机和操作

- 相机：侧偏 3D 动作相机。
- 移动：标准的动作移动，映射到 Godot 默认输入动作。
- 跳跃：谨慎使用，仅在能改善穿越可读性时使用。
- 射击：直接、可读、低摩擦的射击行为。

## 5. 视觉方向

- 低多边形或简单形状 3D 资产。
- 高对比度轮廓。
- 饱和的前景强调色与克制的中性背景。
- 可读性优先于真实感。
- 额外细节应支持战斗清晰度，而不是干扰画面。

## 6. 音频方向

- 短促有力的武器和受击音效。
- 清晰的伤害、死亡、拾取和 UI 确认反馈。
- 音乐应支持快节奏动作和短篇剧情场景。

## 7. 当前生产顺序

1. 保持当前原型场景可加载。
2. 仅在循环稳定后用最终美术替换占位几何体。
3. 添加敌人行为和剧情序列。
4. 添加动画、受击反馈和音频。
5. 打磨关卡流程和最终菜单/结果展示。

## 8. 开发计划链接

- 参见 `docs/Development_Plan.md` 了解按任务展开的发布顺序。
- Phase 1 是当前关注重点，直到可玩的垂直切片完成。

## 9. 更新规则

- 如果某项功能改变了游戏定位、时间预算、视觉语言或内容范围，请更新：
  - `README.md`
  - `agents.md`
  - `docs/art_audio_pipeline.md`
- 如果场景或脚本的变更意味着未来的新规则，请写在此处，而不是保持隐含。

## 10. Boss 战手感规则（2026-05-08）

- Boss 受击有“明显反馈”但不允许被连续子弹推离战场。
- 击退属于视觉反馈层，不应主导 Boss 的战略位移；Boss 的主要位移应来自状态机（机动/撤退/冲刺）。
- 对高频命中启用击退衰减：短时间内连续命中时，后续击退距离递减，避免“无限后退”。
- Boss 运动强制限定在可视战场边界内，避免脱离屏幕后造成战斗中断或可读性下降。

## 11. 外形演进规则（2026-05-08）

- Boss 使用 5 张外形变体图（`boss_01`~`boss_05`），每次出场轮换且避免连续重复同一张。
- 玩家飞机外形按角色等级分档：每 5 级切换一次外形，最多 5 档（`lv01`~`lv05`）。
- 玩家等级提升后，若跨越分档阈值（5/10/15/20 级），本局立即更新飞机外形。

## 12. Boss 战阶段规则（2026-05-08）

- Boss 战是独立波次：Boss 出场时立即清空场上常规敌人、掉落物、小行星与弹幕，避免干扰 Boss 手感。
- Boss 战视觉和音乐与常规战斗分离：进入 Boss 阶段时启用独立背景色与更高压迫感的 BGM，Boss 死亡后恢复。
- Boss 目标击杀时长控制在约 20 秒：血量按玩家当前 DPS 动态估算，避免“瞬秒”或“过长拖战”。
- Boss 机动性优先于被击退：近身时触发脱离，保持中距离压制，不允许被贴脸连击持续压在同一位置。
- Boss 尺寸统一为原模型约 2/3，保证视觉识别与战场活动空间匹配。
