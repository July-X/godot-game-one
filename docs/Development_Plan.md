# 开发计划

本计划记录 `Space Bullet Hell`（2D 俯视角 Roguelike 弹幕射击）的当前状态与后续工作顺序。

> 历史说明：2026-05-01 ~ 05-02 期间本项目曾按「单机 3D 微剧情动作游戏」推进 Phase 1-4，
> 该方向已废弃，旧版本归档在 `backup_3d/`。以下 Phase 描述均为当前 2D 弹幕射击形态。

## 当前状态（v1.3.1+）

裂隙航道首卡后的两波已用同种子实弹对照。贯穿、溅射和威力均有不同走法并保留中路绕行，双人最后确认或超时后仍按 90 个物理帧统一排期。[截击数据与复跑](rift_route.md#首卡后的两波截击)

双人母舰以进场火力确定血盾，护盾期可锁定一名机师发射定向脉冲。四组实弹脚本样本为 2–3 盾，已验证实走躲避、队友打盾和重连恢复预警。真人配合和手机双机待验。[基线与复跑](boss_coop.md)

双人局后台采用 20 秒原局恢复窗。保留连接和重新握手两条路径均校验房主状态再放行输入。手机和平板切应用、锁屏和系统回收待真机验证。[恢复协议与复跑](lan_resume.md)

联机拾取改为按局号和物品 ID 结算。两个画幅互换房主，已检查同帧竞争、指定归属、重复通知和补快照，以及边缘文字。手机和平板真机待验。[时序与复跑](lan_pickup.md)

联机跨画幅保留共享战场，移除了窄长和偏方画面上的连续边线。双进程使用 20:9、4:3 和 16:9 检查四角移动、双指技能与选卡、掉落和救援落点。手机和平板真机待验。[复现场景与验收](architecture.md#跨画幅联机验收)

母舰被致命实弹击中时当帧结算。破盾开放期采用 2.2 倍本体易伤，基础单人实弹样本从 7 盾降到 3 盾。[双端验收与配装对照](boss_shield_rhythm.md#破盾易伤对照)

普通战斗三选一保留左指移动，卡片外的面板空白仍可起手。双进程验证了另一指施放技能、确认选卡和超时。手机实测待复核。[复现与门禁](lan_upgrade_draft.md#三选一打开时的触摸回归)

移动端积分区按系统安全边距和圆角保护排版。16:9、20:9 图形和双进程覆盖左右切口与长分数，手机实测待复核。[布局与复跑](art_audio_pipeline.md#积分区的圆角留白)

裂隙母舰已接入周期护盾和主动攻击。蓄力可打断，发射后继续沿锁定路径。血盾同步、模拟躲避与旧新节奏样本见[周期护盾验收](boss_shield_rhythm.md)。远弹退场单独排期。

手机战斗界面已接入本机安全区、浮动摇杆和居中大卡。母舰主体实拍尺度扩大，碰撞和激光沿用原坐标。模拟触控和双进程回归已覆盖，Android 圆角与手势区待真机确认。[设计与复跑](art_audio_pipeline.md#手机战斗界面与母舰尺度)

终局激光已完成四阶段原倍率实拍。圆端帽、内外圈和收束时刻通过图形探针，房主及加入端通过分阶段恢复。手机真机待验。[样式与复跑](art_audio_pipeline.md#终局激光的像素表现)

裂隙母舰受压侧移已完成单人和真实双进程轨迹对照。已验证 P2 实弹选向、贴边选开阔侧、侧移中受伤与激光接管。真人手感和手机待验。[设计、数据口径与复跑](Design_Decisions.md#裂隙母舰受压侧移)

已修复冰白和护盾火花从父节点原点滑入的首帧偏位。120 帧逐帧实拍和真实局域网延后送达检查都核对了落点。[测量与复跑](art_audio_pipeline.md#静止命中特效的出生坐标)

Android 首卡试玩已接入标题页选版。两种画幅通过无参数触摸选卡、同版重试及返回换版。现有 Android 预设已用 JDK 17 在独立目录导出并验签，手机安装与真人试玩待验。[导出步骤](first_card_trial.md#android-调试导出) · [五分钟试玩单](first_card_playtest.md)

## 双人联机的战场边界

在 `24ed86a` 上复跑 1280×720 与 1600×720 双进程，交换房主后都是窄端丢失队友。窄端飞机停在 x=1256，宽端飞机能到 x=1576。

房主在大厅开局消息里给出 1280×720 逻辑战场。两端用相同的世界坐标移动、生成敌人、计算弹道。宽屏居中取景，多出的区域显示星空和界面。窗口缩放只改变显示映射。单机与首卡试飞沿用本地视口。

2026-11-21 在 macOS、Godot 4.6.2 上实跑双进程 ENet。宽端和窄端分别当房主，无窗口每组通过 29 项，真实窗口每组通过 36 项，两端均正常退出。两架飞机通过输入抵达四边，主炮在 x=1270 向左反弹，敌弹首次越过 x=1340 后在 x=1344 回收。Boss 从 (640, −80) 进入，两端都停在 (640, 160)。宽屏两侧各有 160 单位星空；窗口改为 960×600 后，同一次模拟触摸在 0.75 倍画布上仍给出 (0.75, 0) 的摇杆输入。

常规联机 40 项、战斗反馈联机 19 项、波次 25 项、难度 14 项、桌面移动交互 13 项均通过。首卡脚本的 8 组路径共通过 194 项，普通局与首卡试飞的按键、超时场景共 4 组通过。手机双机、鸿蒙近场、弱网和跨版本联机仍待验证。

联机三选一已改为房主发卡并结算。加入端重复收到同级快照时继续展示当前批次，确认后的卡层数由房主同步。专项用实弹击杀、模拟触摸和超时验证这条链路。[复现与验收](lan_upgrade_draft.md)

双人救援改为靠近坠机点触发。双方共用 3 次，倒地时间和次数由房主同步，最后 5 秒用橙色显示。[规则与双端验证](lan_rescue.md)

在仓库根目录复跑。图形用例的第三个参数是已有目录，两端各写一张原尺寸截图。探针让两架飞机停在左右边界，并让房主的 Boss 完成入场动画后停驻，等待加入端的坐标也收敛再取图。

## 工作规则

- 联机改动必须区分「玩家死亡」与「玩家断线」两条流程，不得合并。
- 改玩法 / 联机 / 美术方向时，先改 `docs/Design_Decisions.md`，再改实现。
- 代码结构以 `docs/architecture.md` 为准。
- HUD / 场景类改动必须跑主场景运行验证，`--quit` 不足以覆盖 `_ready` / `_process` 链路。

## 联机回归验证（2026-09-27）

`tests/run_probe.sh` + `tests/lan_probe.gd`，两个 headless 进程在本机回环跑真实 ENet：

```bash
tests/run_probe.sh 7788     # 全绿才 exit 0
```

常规双进程用例共 40 项断言（房主 24 项、加入端 16 项）。

- 两端均能识别 P1 和 P2 雨燕，同一个核心只在拾取者一侧出现一次断环
- P1 被 Boss 终局激光内圈秒杀后，P2 会话存活 10 秒不掉线、不 Game Over、不回退单机
- 记分牌 / 排行榜按 `P1`/`P2` 槽位显示，不暴露随机 ENet peer_id
- 终局激光蓄力 120 物理帧（2.0s）、推进阶段仅尖端命中（开火后 32 帧才判定）
- 束外玩家零伤害：推进 3s + 持续 10s 全程逐帧采样 P2 血量
- 精英在场时 Boss 触发进入 `_pending_boss_level`，精英死亡后自动补发
- 玩家同步归属：远端幽灵跟随 Host / 本机玩家不被幽灵坐标覆盖 / Host 幽灵被客户端驱动
- 两端玩家节点数恒为 2，且不得再挂引擎 `MultiplayerSynchronizer`

由该验证暴露并修复的真实缺陷（详见 `docs/architecture.md` §11.7 与 `CHANGELOG.md`）：

- 玩家位置同步：客户端原本约 2/3 概率完全拿不到 Host 的玩家节点
- 权威错位：Host 把 P2 幽灵坐标灌到客户端本机玩家上
- `pool.gd` 空池取用崩溃、`powerup.gd` 入树前设置样式空引用
- `pool.gd` 名存实亡的池化与 60 个常驻孤儿节点、`powerup.gd` 两个只写不读的死字段
