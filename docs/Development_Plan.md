# 开发计划

本计划描述了当前游戏切片的工作顺序。它有意保持狭窄：目标是交付一个完整的短游戏，而不是在循环稳定之前扩大范围。

## Phase 1：可玩垂直切片

目标：让游戏能够启动、游玩、战斗并完成。

工作项：

1. 保持项目在 Godot 4 中可加载。
2. 让玩家能够移动、跳跃和射击。
3. 让敌人能够巡逻、追击、受击和死亡。
4. 添加胜利和失败条件。
5. 添加简单的 HUD 和剧情文本。

预期结果：

- 一个紧凑的关卡可以从头到尾打通。
- 玩家一眼就能理解目标。
- 即使使用占位美术，战斗反馈也是可读的。

## Phase 2：叙事和流程

目标：把垂直切片变成一个短篇微剧情游戏。

工作项：

1. 添加开场和结尾片段。
2. 添加 2 到 4 个短场景段落。
3. 调整节奏，使完整流程保持在 1 小时以内。
4. 添加结果画面和重启流程。

### Phase 2 子任务（已规划）

- [x] 标题画面（"按 Enter 开始"）
- [x] 开场简报序列
- [x] 关卡内多个剧情触发器节点
- [x] 关卡结束结果画面（带统计）
- [x] 状态间的平滑过渡

## Phase 3：美术生产

目标：在保持当前风格方向的前提下，用最终美术替换占位资源。

### Phase 3 子任务

- [x] 玩家低多边形模型（躯干+头+四肢+枪，多部件组合）
- [x] 敌人低多边形模型（躯干+头+四肢，带黄色护目镜）
- [x] 光照增强（主光+补光，硬阴影，高对比度）
- [x] 后处理（ACES 色调映射，暗色背景，微弱辉光）
- [x] 玩家奔跑动画（腿臂摆动，身体起伏）
- [x] 玩家射击 recoil 动画（枪口上跳）
- [x] 敌人受击闪光（全身部件白色 emission 闪烁）
- [x] 敌人死亡动画（全身红色 emission + 缩小消失）

## Phase 4：音频与打磨

目标：完成体验。

工作项：

1. 添加武器、受击、爆炸、UI 和环境音效。
2. 添加 2 到 3 个短 BGM 循环。
3. 调整难度、受击时机和过渡。
4. 修复 Bug 并准备可玩构建。

## 工作规则

- 在 Phase 1 完成之前，不要扩展新系统。
- 当计划变化时更新本文档。
- 如果新增或移除里程碑，同步更新 `README.md` 和 `docs/Design_Decisions.md`。
