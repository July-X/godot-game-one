# 开发计划

本计划描述了当前游戏切片的工作顺序。它有意保持狭窄：目标是交付一个完整的短游戏，而不是在循环稳定之前扩大范围。

## Phase 1：可玩垂直切片

目标：让游戏能够启动、游玩、战斗并完成。

工作项：

1. 保持项目在 Godot 4 中可加载。
2. 让玩家能够移动、跳跃和射击。
3. 让敌人能够巡逻、追击、受击和死亡。
4. 添加胜利和失败条件。
5. 添加简单的 HUD 和剧情文本。

预期结果：

- 一个紧凑的关卡可以从头到尾打通。
- 玩家一眼就能理解目标。
- 即使使用占位美术，战斗反馈也是可读的。

## Phase 2：叙事和流程

目标：把垂直切片变成一个短篇微剧情游戏。

工作项：

1. 添加开场和结尾片段。
2. 添加 2 到 4 个短场景段落。
3. 调整节奏，使完整流程保持在 1 小时以内。
4. 添加结果画面和重启流程。

### Phase 2 子任务（已规划）

- [x] 标题画面（"按 Enter 开始"）
- [x] 开场简报序列
- [x] 关卡内多个剧情触发器节点
- [x] 关卡结束结果画面（带统计）
- [x] 状态间的平滑过渡（屏幕淡入淡出）

## Phase 3：美术生产

目标：在保持当前风格方向的前提下，用最终美术替换占位资源。

工作项：

1. 建模玩家、敌人、环境道具和关键场景部件。
2. 添加动画片段和状态过渡。
3. 改进光照、后处理和可读性。
4. 保持 Contra 风格 3D 视觉语言的一致性。

## Phase 4：音频与打磨

目标：完成体验。

### Phase 4 子任务

- [x] 程序化音效系统（SFX Autoload，8-bit 风格：射击/受击/敌人受伤/敌人死亡/玩家受伤/UI 确认/爆炸）
- [x] 伤害数字弹出（3D Label，金色敌人/红色玩家，上升渐隐）
- [x] 子弹拖尾（发光材质 + 动态 MeshInstance3D 拖尾条）
- [x] 敌人 AI 优化（巡逻端点停顿 0.8s）
- [x] HUD 伤害反馈（底部 "-N HP" 渐隐文本）
- [x] BGM 程序化生成（标题/游戏/结果主题，自动循环）
- [x] 最终 Bug 修复和平衡调整

## 工作规则

- 在 Phase 1 完成之前，不要扩展新系统。
- 当计划变化时更新本文档。
- 如果新增或移除里程碑，同步更新 `README.md` 和 `docs/Design_Decisions.md`。
