# 开发计划

本计划记录 `Space Bullet Hell`（2D 俯视角 Roguelike 弹幕射击）的当前状态与后续工作顺序。

> 历史说明：2026-05-01 ~ 05-02 期间本项目曾按「单机 3D 微剧情动作游戏」推进 Phase 1-4，
> 该方向已废弃，旧版本归档在 `backup_3d/`。以下 Phase 描述均为当前 2D 弹幕射击形态。

## 下一步候选

1. 双机联机性能压测：加入端帧率 ≥ 60 的量化结论（目前仍是待办，见下方 M4）
2. 鸿蒙真机双端联调与稳定性测试（依赖仓库外原生插件）
3. 关卡节奏扩充（乐句 + 阵型已完成，剩余见 `docs/level_design_proposal.md`）：
   3.1 阵型 × 构筑耦合（按卡池权重偏置阵型，~60 行，最高性价比）
   3.2 精英 / Boss 预告倒计时条（~120 行）
   3.3 封顶精英与 Boss 的难度乘区（~20 行，数值失控口）
   3.4 小行星纳入编排 + 同屏上限（~40 行）
   3.5 关卡内契约（可选支线，~200 行）
   3.6 场地事件（危险区 / 星核贪利点）
   3.7 Boss 弹幕主题随机组合（纯配置，零新美术）
4. 外部美术资产替换（Boss / 玩家外形已先行，其余仍为程序化占位）
5. 清理 `backup_3d/` 等历史存档

## 工作规则

- 联机改动必须区分「玩家死亡」与「玩家断线」两条流程，不得合并。
- 改玩法 / 联机 / 美术方向时，先改 `docs/Design_Decisions.md`，再改实现。
- 代码结构以 `docs/architecture.md` 为准。
- HUD / 场景类改动必须跑主场景运行验证，`--quit` 不足以覆盖 `_ready` / `_process` 链路。

## 联机回归验证（2026-09-27）

`tests/run_probe.sh` + `tests/lan_probe.gd`，两个 headless 进程在本机回环跑真实 ENet：

```bash
tests/run_probe.sh 7788     # 全绿才 exit 0
```

共 **36 项断言**（host 22 + client 14），覆盖并已全部通过（连续多轮复现）：

- P1 被 Boss 终局激光内圈秒杀后，P2 会话存活 10 秒不掉线、不 Game Over、不回退单机
- 记分牌 / 排行榜按 `P1`/`P2` 槽位显示，不暴露随机 ENet peer_id
- 终局激光蓄力 120 物理帧（2.0s）、推进阶段仅尖端命中（开火后 32 帧才判定）
- 束外玩家零伤害：推进 3s + 持续 10s 全程逐帧采样 P2 血量
- 精英在场时 Boss 触发进入 `_pending_boss_level`，精英死亡后自动补发
- 玩家同步归属：远端幽灵跟随 Host / 本机玩家不被幽灵坐标覆盖 / Host 幽灵被客户端驱动
- 两端玩家节点数恒为 2，且不得再挂引擎 `MultiplayerSynchronizer`

由该验证暴露并修复的真实缺陷（详见 `docs/architecture.md` §11.7 与 `CHANGELOG.md`）：

- 玩家位置同步：客户端原本约 2/3 概率完全拿不到 Host 的玩家节点
- 权威错位：Host 把 P2 幽灵坐标灌到客户端本机玩家上
- `pool.gd` 空池取用崩溃、`powerup.gd` 入树前设置样式空引用
- `pool.gd` 名存实亡的池化与 60 个常驻孤儿节点、`powerup.gd` 两个只写不读的死字段
