# 首卡后的第一波

从标题页进「首卡试飞」，按平时的方式移动和开火。第十次击杀升到二级，场上残敌和子弹退场，已掉落的道具、玩家位置和成长保留。此时可以读完卡面，再按 1、2、3 或点卡。按 4 或点「数值对照」可以改选威力卡。十秒未操作会自动选第一张。

## 同一波，四种走法

选定首卡后约九秒内，左侧三架纵排，右侧两架轻机向中间的散射者聚拢。它们按选定后的物理帧依次出生，六个时刻是 12、34、56、72、84、96。第 278 帧敌机开始撤离，右侧出现一秒预告线。三轮扇弹在第 338、368、398 帧发出，使用现有的 430 像素/秒慢弹。中间留有整条通道。第 550 帧恢复普通导演，后续升级照常从原卡池抽取。单独练习时可以直接重新选卡。

| 首卡与操作 | 1280×720 实测 | 同路线对照 |
| --- | --- | --- |
| 贯穿弹芯。先横移到左路，再转向纵队 | 有一发实弹先后打中两架。第 145 帧击毁纵队最后一架 | 威力卡也能清掉三架，第 158 帧完成，每发只打中一架 |
| 溅射弹头。先在右路等两翼靠拢，再向上打中央散射者 | 第 225 帧中央和两翼同时被击毁，两翼在炮弹直接碰撞范围外 | 同一帧威力卡只击毁中央一架 |
| 擦弹专注。沿第一束扇弹的外侧飞 | 航迹离弹道最近 40 像素，三轮各擦一次，叠一层，射击间隔缩短 4% | 同一航迹持威力卡时擦弹为零。持擦弹卡走中路同样为零 |
| 威力 +3。沿中路向上 | 全程 50/50 生命，最近的敌弹约 195 像素 | 擦弹卡沿此航迹也能无伤通过 |

八组测试都核对了实际入场的六架敌机和九发扇弹。同路线的两种卡还逐帧比对了玩家位置，精度为 0.01 像素。四种走法均由脚本给出。是否看懂卡面、选卡后会不会自行改变走位，要靠真人试玩观察。

## 原版首卡、精英和 Boss 的时间

普通局的追加采样以 `53c0b65` 为起点，已追踪到首只 Boss 的死亡信号。每局从一级开始，记录候选及选择方式。下一波里分别核对实弹带上了哪张卡、何时命中队员，以及何时出现这张卡才有的效果。选卡时战斗继续，展示到确认的时间单列。首领的入场等待、可交火时间、护盾免伤和提前死亡均有逐帧记录。[首只 Boss 采样与试玩单](boss_pace_baseline.md)

基线为 `b413d613`。本机 Godot 4.6.2，逻辑视口 1280×720，每秒 60 个物理帧。游戏、导演和抽卡器的随机源分别设为 1121。标定射手留在出生位置，自动朝向最近目标并用原主炮射击。为走完整段，脚本延长了玩家无敌时间；击杀、掉落、入场上限和首领触发都走游戏逻辑。

原卡池首轮给出过载扳机、贯穿弹芯、强化装甲。试飞依次给出贯穿、溅射、擦弹，威力卡有单独的对照入口。脚本在发送按键期间标记输入来源；超时组从未发送选卡输入。每次抽卡的实际候选和选择结果都写入日志。

原版两轮都记录了 61 架导演投放的敌机，阵形、敌种与坐标全数相同。最先错开的是第 19 架钳形队散射者。它在 A 的第 1485 帧排期、第 1493 帧出生，在 B 的第 1478 帧排期、第 1486 帧出生。普通导演保留在场上限，遇到精英还会暂停推进。固定片段独立使用六架出生轨迹。[两轮逐架排期、名义到期与实际出生](first_card_baseline.csv)

最初沿用无窗口模式的默认方形视口，两次各投放了 65 架。上表和逐架记录都取自显式设置为 1280×720 的运行。

原版 A、B 的累计击杀计数都在 10 时出首卡，24、50、78 时请求精英，85 时请求首只 Boss。试飞里的六架靶机在击毁当帧就移出目标组，避免后续炮弹或溅射再次记分。完整流程里清掉六架后计数从 10 到 16，下一波交还普通导演。

## 复跑

在项目根目录执行。只有复跑脚本需要 Python 3，仅用标准库。

```sh
# 从一级开始试玩，或从首卡开始反复对照
godot --path . res://scenes/first_card_trial.tscn
godot --path . res://scenes/first_card_trial.tscn -- --from-draft

# 八组同阵对照，加上普通局和试飞各自的按键、超时流程
python3 tests/run_first_card_probe.py /tmp/first-card-results

# 单独录制一条。可将 pierce 换成 splash、graze_focus 或 power
godot --path . --windowed --resolution 1280x720 --fixed-fps 60 \
  --write-movie /tmp/pierce.avi res://tests/first_card_wave_probe.tscn -- pierce
```

在原版工作树复测时，把本版的 `tests/first_card_timing.gd` 和同名 `.tscn` 放进原版副本，再执行下面的命令。两份输出文件分别保留。逐帧日志中的 `scheduled_tick` 是进入导演队列的时间，`nominal_due_tick` 是排期时按 60 帧/秒换算的到期时间，`birth` 取自节点实际加入场景的时刻。

```sh
godot --headless --fixed-fps 60 --path . res://tests/first_card_timing.tscn -- input /tmp/stock-a.csv
godot --headless --fixed-fps 60 --path . res://tests/first_card_timing.tscn -- input /tmp/stock-b.csv
```
