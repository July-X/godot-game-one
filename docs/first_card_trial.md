# 首卡后的第一波

从标题页点「首卡试飞」，选择「试飞 A」或「试飞 B」。两版都直接到同一个首选画面。按 1、2、3 或点卡，按 4 或点「数值对照」可选威力卡。十秒未操作会自动选第一张。触屏上可以在等首选时走位，但不会提前射击或推进波次；第二根手指点卡后，战斗接着当前走位。片段结束时收起摇杆，可重试同版，返回标题后可换版。

直接运行原试飞场景时仍从一级开始。第十次击杀升到二级，场上残敌和子弹退场，已掉落的道具、玩家位置和成长保留。固定片段结束后恢复普通导演。

## 同一波，四种走法

选定首卡后约九秒内，左侧三架纵排，右侧两架轻机向中间的散射者聚拢。它们按选定后的物理帧依次出生，六个时刻是 12、34、56、72、84、96。第 278 帧敌机开始撤离，右侧出现一秒预告线。三轮扇弹在第 338、368、398 帧发出，使用现有的 430 像素/秒慢弹。中间留有整条通道。第 550 帧恢复普通导演，后续升级照常从原卡池抽取。单独练习时可以直接重新选卡。

| 首卡与操作 | 1280×720 实测 | 同路线对照 |
| --- | --- | --- |
| 贯穿弹芯。先横移到左路，再转向纵队 | 有一发实弹先后打中两架。第 145 帧击毁纵队最后一架 | 威力卡也能清掉三架，第 158 帧完成，每发只打中一架 |
| 溅射弹头。先在右路等两翼靠拢，再向上打中央散射者 | 第 225 帧中央和两翼同时被击毁，两翼在炮弹直接碰撞范围外 | 同一帧威力卡只击毁中央一架 |
| 擦弹专注。沿第一束扇弹的外侧飞 | 航迹离弹道最近 40 像素，三轮各擦一次，叠一层，射击间隔缩短 4% | 同一航迹持威力卡时擦弹为零。持擦弹卡走中路同样为零 |
| 威力 +3。沿中路向上 | 全程 50/50 生命，最近的敌弹约 195 像素 | 擦弹卡沿此航迹也能无伤通过 |

八组测试都核对了实际入场的六架敌机和九发扇弹。同路线的两种卡还逐帧比对了玩家位置，精度为 0.01 像素。四种走法均由脚本给出。是否看懂卡面、选卡后会不会自行改变走位，要靠真人试玩观察。

## 行动提示对照

两版在确认前使用相同的卡面和起点。B 的顶部中央只有一行文字，位于战斗物体下层，随本机安全区定位。贯穿和溅射在确认后第 1 至 179 帧可见。擦弹在第 188 至 361 帧可见，跨过原有扇弹预告和第一轮发射。A 和威力卡无提示。直接运行场景也可用 `--trial-hint` 开启 B 的提示。

| 卡 | B 版行动提示 |
| --- | --- |
| 贯穿弹芯 | 去左侧对齐纵队 |
| 溅射弹头 | 去右侧等敌机靠拢 |
| 擦弹专注 | 等扇弹，沿弹幕外缘飞 |

菜单试飞输出本地 `[TRIAL_EVENT]`，直接运行场景时用 `--trial-log` 开启。以确认帧为零，记录选择来源 `key`、`tap` 或 `timeout`，以及提示起止、首次结果和本波结束。贯穿以同一实弹经过两架不同靶机为准，溅射以原伤害分支确实扣到邻机的生命为准，擦弹读实际新增层数。擦弹的固定边缘航迹还与同路威力卡比对。失血累计从确认算起，治疗不冲销已失去的生命，护盾损失另按原规则处理。结束记录的 `result_tick=-1` 代表这波没有观察到特有效果。[首张卡试玩单](first_card_playtest.md)

### 本机结果

Mac 上用 Godot 4.6.2 复跑。16:9 的原八组 A/B 对照共 4,400 个战斗帧，20:9 的四组共 2,200 帧。逐帧核对玩家位置、朝向、速度、生命值、护盾、击杀数、靶机位置与生命值，以及双方弹体位置、方向、弹速和命中状态。12 对全部一致，六架靶机和九发扇弹在每次运行中都按原表出生。16:9 的 A 与 `56c5c29` 的八组出生、航迹和结果摘要逐行一致。

| 首次结果 | 16:9，A 与 B | 20:9，A 与 B |
| --- | --- | --- |
| 同一发贯穿两架 | 第 137 帧，2.28 秒 | 第 145 帧，2.42 秒 |
| 溅射扣到邻机生命 | 第 225 帧，3.75 秒 | 第 225 帧，3.75 秒 |
| 擦弹新增一层 | 第 479 帧，7.98 秒 | 第 481 帧，8.02 秒 |

这些固定走法的首次结果与整波累计失血均为零。真实 Godot 窗口的八对截图中，三张构筑卡的像素差落在顶部文字范围，威力卡的两版逐像素相同。两种画幅的模拟触屏各通过 13 项图形验证，含按住摇杆点卡、左右移动、松手、重试和离场。累计失血另用可控的两点扣血后治疗复验。

普通局与试飞各自的按键、超时四条流程，加上 B 版试飞的两条流程，均到达首只 Boss 的首次实弹受伤。B 版超时实例在第 415 帧开卡，第 1014 帧自动选贯穿，日志记为 `timeout`。完整流程继续使用原导演和实时时间机制。常规联机 40/40、反馈联机 25/25、桌面移动端交互门禁 13/13，项目导入和主场景启动通过。

所有走位与输入由脚本驱动。真人能否在看到提示后找对时机、自己说出效果，留给试玩。手机触屏尚未实测。

### 标题入口回归

无游戏参数启动，宽屏无窗口通过 19 项，1280×720 和 1600×720 真窗口各通过 20 项。探针从标题实际发送触摸事件，走项目的触摸转鼠标链路，核对选版、取消、同一个首选位置与十秒倒计时、点按来源、同版重试及返回换版。也复跑了键盘选择、鼠标返回和带不对称边距的安全区。两个画幅各通过 12 项双指输入及清理检查。

原固定路线再次比对 12 对、6,600 帧，敌机、弹道、走位及四张卡的结果一致。普通局和完整试飞的六条流程都来到首只 Boss 的首次实伤。移动端交互 13/13、常规联机 40/40、项目载入和主场景运行通过。以上输入来自 Mac 模拟。

## 原版首卡、精英和 Boss 的时间

普通局的追加采样以 `53c0b65` 为起点，已追踪到首只 Boss 的死亡信号。每局从一级开始，记录候选及选择方式。下一波里分别核对实弹带上了哪张卡、何时命中队员，以及何时出现这张卡才有的效果。选卡时战斗继续，展示到确认的时间单列。首领的入场等待、可交火时间、护盾免伤和提前死亡均有逐帧记录。[首只 Boss 采样与试玩单](boss_pace_baseline.md)

基线为 `b413d613`。本机 Godot 4.6.2，逻辑视口 1280×720，每秒 60 个物理帧。游戏、导演和抽卡器的随机源分别设为 1121。标定射手留在出生位置，自动朝向最近目标并用原主炮射击。为走完整段，脚本延长了玩家无敌时间；击杀、掉落、入场上限和首领触发都走游戏逻辑。

原卡池首轮给出过载扳机、贯穿弹芯、强化装甲。试飞依次给出贯穿、溅射、擦弹，威力卡有单独的对照入口。脚本在发送按键期间标记输入来源；超时组从未发送选卡输入。每次抽卡的实际候选和选择结果都写入日志。

原版两轮都记录了 61 架导演投放的敌机，阵形、敌种与坐标全数相同。最先错开的是第 19 架钳形队散射者。它在 A 的第 1485 帧排期、第 1493 帧出生，在 B 的第 1478 帧排期、第 1486 帧出生。普通导演保留在场上限，遇到精英还会暂停推进。固定片段独立使用六架出生轨迹。[两轮逐架排期、名义到期与实际出生](first_card_baseline.csv)

最初沿用无窗口模式的默认方形视口，两次各投放了 65 架。上表和逐架记录都取自显式设置为 1280×720 的运行。

原版 A、B 的累计击杀计数都在 10 时出首卡，24、50、78 时请求精英，85 时请求首只 Boss。试飞里的六架靶机在击毁当帧就移出目标组，避免后续炮弹或溅射再次记分。完整流程里清掉六架后计数从 10 到 16，下一波交还普通导演。

## 复跑

在项目根目录执行。只有复跑脚本需要 Python 3，仅用标准库。

```sh
# 从一级开始试玩，或从首卡开始反复对照
godot --path . res://scenes/first_card_trial.tscn
godot --path . res://scenes/first_card_trial.tscn -- --from-draft

# 原八组路线逐对比较 A/B，宽屏复跑四组，另跑按键、超时、触摸和重试
python3 tests/run_first_card_probe.py /tmp/first-card-results

# 走实际标题入口，使用项目的触摸转鼠标路径，无游戏参数
godot --headless --fixed-fps 60 --path . res://tests/first_card_entry_probe.tscn

# 同一起点的短试玩，分别从选卡开始
godot --path . res://scenes/first_card_trial.tscn -- --from-draft --trial-log
godot --path . res://scenes/first_card_trial.tscn -- --from-draft --trial-log --trial-hint

# 宽屏同构图截图，输出目录需已存在。A 省去 --trial-hint。
godot --path . --windowed --resolution 1600x720 --fixed-fps 60 --disable-vsync \
  --audio-driver Dummy res://tests/first_card_wave_probe.tscn -- graze_focus --wide \
  --trial-hint --trial-log --capture=/tmp/first-card-capture

# 同画幅验证模拟双指输入和重试
godot --path . --windowed --resolution 1600x720 --fixed-fps 60 --disable-vsync \
  --audio-driver Dummy res://tests/first_card_controls_probe.tscn -- --wide --from-draft \
  --trial-hint --trial-log --capture=/tmp/first-card-touch.png

# 单独录制一条。可将 pierce 换成 splash、graze_focus 或 power
godot --path . --windowed --resolution 1280x720 --fixed-fps 60 \
  --write-movie /tmp/pierce.avi res://tests/first_card_wave_probe.tscn -- pierce
```

在原版工作树复测时，把本版的 `tests/first_card_timing.gd` 和同名 `.tscn` 放进原版副本，再执行下面的命令。两份输出文件分别保留。逐帧日志中的 `scheduled_tick` 是进入导演队列的时间，`nominal_due_tick` 是排期时按 60 帧/秒换算的到期时间，`birth` 取自节点实际加入场景的时刻。

```sh
godot --headless --fixed-fps 60 --path . res://tests/first_card_timing.tscn -- input /tmp/stock-a.csv
godot --headless --fixed-fps 60 --path . res://tests/first_card_timing.tscn -- input /tmp/stock-b.csv
```

## Android 调试导出

1. 使用 Godot 4.6.2 及匹配的导出模板。Android SDK（软件开发工具包）路径指向本机 SDK 根目录，Java SDK 路径指向 JDK 17。本机分别使用 `~/Library/Android/sdk` 和 `~/.sdkman/candidates/java/17.0.4-oracle`，构建工具是 SDK 35、Build Tools 35.0.1 和模板自带的 Gradle 8.11.1。[Godot 4.6 Android 环境](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_android.html)
2. 在项目导出窗口选择已有的 `Android` 预设，使用 Gradle Build、`arm64-v8a` 和 APK 格式。新工作目录若缺少 `android/build/gradlew`，先安装对应版本的 Android 构建模板。保留仓库定制的 `AndroidManifest.xml` 与 `HarmonyNearbyGamePlugin.kt`，装完模板后核对两份文件。[Gradle 构建模板](https://docs.godotengine.org/en/4.6/tutorials/export/android_gradle_build.html)
3. 导出时选择 Debug，并写到新路径。已配好环境后，也可在项目根目录执行下面的命令。

```sh
trial_apk_dir="$(mktemp -d "${TMPDIR:-/tmp}/space-bullet-hell-trial.XXXXXX")"
godot --headless --path . --export-debug Android "$trial_apk_dir/Space-Bullet-Hell-Trial-AB-debug.apk"
```

本机导出验证使用临时项目副本和独立 Godot.app。把 `_sc_` 放在副本 Godot.app 的同级目录，Godot 4.6.2 会从同级 `editor_data` 读配置与模板。将 JDK 17 和 SDK 路径写入该目录的编辑器设置，导出进程也使用同一 JDK 17。现有 APK、全局 Godot 设置和 SDKMAN 的 Java 默认链接均已核对。[Godot 4.6.2 路径实现](https://github.com/godotengine/godot/blob/4.6.2-stable/editor/file_system/editor_paths.cpp#L122-L157)

调试 APK（Android 安装包）已导出并通过 ZIP 完整性和 `apksigner` 验签。包名 `com.gamedev.spacebullethell`，版本 `1.1.0`，最低 API 24、目标 API 35。包内确认有桌面启动入口 `MAIN/LAUNCHER`、标题及 A/B 两个场景。验证包使用临时调试证书，覆盖手机已有同名应用时需沿用原签名。手机安装、启动和真人试玩留给现场验收。[Android 签名要求](https://developer.android.com/studio/publish/app-signing)
