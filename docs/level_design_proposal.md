# 关卡设计优化方案（2026-09-28）

> 目标：**在不加难度的前提下增加趣味性**。
> 本文所有"已完成"项都已在代码里落地并有 headless 门禁；
> "待落地"项是按优先级排好的后续建议，每条都带证据、成本和验收标准。

---

## 1. 现状体检：问题不在数值，在**结构**

改造前，`main.gd` 里全部杂兵投放由两个定时器负责：

```gdscript
_enemy_spawn_timer = max(1.2 - GameState.level * 0.06, 0.45)  # 每秒 1 只
if _difficulty_timer > 8.0: _difficulty_timer = 0.0;  _spawn_enemy_if_below_cap()  # 每 8 秒补 1 只
```

敌人类型 `randi() % 3`、出生点四条边各 1/4 概率。看起来能跑，但有三个结构性问题：

### 1.1 四条压力通道在 L13~L56 全部走完增长并触顶

| 通道 | 公式 | 饱和点 |
|---|---|---|
| 刷怪间隔 | `max(1.2 - 0.06L, 0.45)` | **L13 触底** |
| 敌人开火 CD | `max((2.0 - 0.12L) / mult, 0.4)` | **L10~L14 触底** |
| 同屏上限 | `ENEMY_SCREEN_CAP = 20` | 恒定 |
| 敌速 | `clamp(40+3L+8T, 40, 208)` | **L51~L56 触顶** |
| 敌人血量 | `(1 + L/2 + T) * mult` | 无上限 —— **唯一还在涨的** |

**结论：35 个等级（L15~L50）里，玩家的"体感压力"几乎完全不变，只有敌血在涨。**
这不是难度不够，是**难度只有一个维度**。弹幕射击的乐趣来自强度的时间分布与空间形状，
而这两样当前都是常数。

### 1.2 没有形状：屏幕上永远不会出现图案

出生点四边随机 ⇒ 敌人永远是散点。弹幕射击的画面美感与"可读的躲避预案"都依赖
**成组的、有方向的图案**（一排横线压过来 / 两侧同时夹击 / 一圈弹幕环合拢）。
当前没有任何机制能表达"这一波是什么"。

### 1.3 调研报告也没有覆盖这一块

`docs/research_bullet_hell_fun_2026-09-27.md` 的建议集中在难度曲线、手感反馈链、
构筑与 Meta，**没有波次编排 / 关卡结构 / 喘息窗口的框架**。
所以这不是"照着报告实现"，是自建的数据层。

## 2. 已落地：波次编排器（Wave Director）

实现：`scripts/wave_director.gd`，接入 `main.gd` 的 `_tick_wave_director()`。

### 2.1 结构：一关 = 一段 4 拍乐句

```
起拍 SETUP  →  涨潮 SURGE  →  浪峰 CREST  →  退潮 LULL
  0.910            1.254            1.486           0.350      ← 相对章节均值的倍率
                   每拍 16 秒，一章 64 秒
```

**关键约束：`PHASE_SHAPE` 四数之和恰好等于 4**，于是

> 「一章的平均投放速率 ≡ 改造前随机刷怪的速率」，误差 0.000%。

这是本次改造最重要的一条契约：**只重新分配强度在时间轴上的分布，不偷偷加难度。**
它由 `tests/wave_probe.gd` 的 `chapter_mean_matches_legacy` 门禁守住（1~60 级全对）。

峰值/谷值比 **4.25×**（浪峰 1.486 vs 退潮 0.350）——这就是"张弛"。
没有退潮就没有浪峰的压迫感；旧版是一条恒定直线，所以玩十分钟和玩一分钟手感相同。

### 2.2 阵型：让屏幕上出现图案

6 种阵型，按拍限定词表：

| 阵型 | 形状 | 敌型 | 玩家该怎么打 |
|---|---|---|---|
| `line` 一字横排 | 上方排成一线 | 狙击手（950 快档） | 横向找空档，整排同时点名 |
| `column` 纵列 | 上方纵深推进 | 环绕者（430 慢档） | 纵深预警，逐个点掉 |
| `vee` V 字合围 | 下方两翼包抄 | 散射者（780 中档） | 被压进口袋，往上/侧突围 |
| `pincer` 两侧对进 | 左右同时压 | 散射者 | 只能往上下逃 |
| `ring` 弧线展开 | 上方抛物弧 | 环绕者 | 六连慢弹合成弹幕环，读环走位 |
| `swarm` 蜂群 | 四边随机散点 | 狙击手 | 涨潮段填充背景压力 |

配对原则：**阵型看起来像它在做的事**。`line` 是"一排针"，`ring` 是"一圈环"。
玩家看到形状就该知道往哪躲——这是当前代码完全没有的能力。

所有出生点强制在**屏幕外 44px**（`spawn_points_offscreen` 逐点断言）。
弹幕射击最忌讳贴脸刷怪：战败感必须来自"我没打好"，不能来自"被偷袭"。

### 2.3 章节主题：改的是"怎么躲"，不是"躲不躲得过"

每 5 级（与 Boss 节奏对齐）换一个主题，三个倍率同时动：

| 章节 | 主题 | 敌弹速度 | 敌人血量 | 开火频率 | 手感变化 |
|---|---|---|---|---|---|
| 1 | 压制 | ×1.00 | ×1.00 | ×1.00 | 基准 |
| 2 | 超载 | ×1.10 | ×0.92 | ×1.15 | 弹幕更密更快，但敌人更脆 → 逼你抢输出窗口 |
| 3 | 蜂群 | ×0.94 | ×1.08 | ×0.90 | 慢弹厚血 → 逼你拉开距离打 |
| 4 | 离子风暴 | ×1.16 | ×0.96 | ×1.05 | 极限弹速 + 仍可击破 → 考验闪避时机 |

倍率全部锁在安全区间（弹速 ≤1.25、血量 ≥0.85、开火 ≥0.85），
由 `chapter_theme_in_range` 门禁守住。主题只改变**应对方式**，
不改"能不能躲"——这是与"直接加难度"的本质区别。

### 2.4 表现层

- HUD 新增乐句读数：`起拍 · 第 2 章 · 37%`，颜色随拍变化
- 浪峰 / 退潮换拍时弹横幅（`浪峰来袭` / `退潮 · 喘息窗口`）
- 换拍横幅只播这两拍：玩家需要知道**边界**，起拍/涨潮每次都弹会变成噪音

### 2.5 联机

编排器**只在 Host 权威运行**，出怪点照旧走既有 `_rpc_spawn_enemy` 广播，
**不新增任何同步包**（只有 `bullet_speed_mult` 一个新字段挂在已有生成包里）。
客户端的乐句读数由 Host 的 `phase_changed` 经现有横幅 RPC 播报。

## 3. 待落地方案（按性价比排序）

### P0 · 阵型 × 构筑耦合 ⭐最高性价比

**问题**：现在 10 张卡让 build 变了打法，但关卡不会响应 build。
选了"贯穿弹芯"（应该贴脸），关卡里却没有值得贴脸的密集编队。

**方案**：让编排器读取 `GameState.get_card_stacks()`，据此微调阵型权重：
- 有 `pierce` / `splash` → 浪峰拍偏向 `line` / `vee` / `pincer`（密集编队）
- 有 `homing` → 偏向 `column`（纵深，玩家站桩就能收）
- 有 `graze_focus` → 退潮拍多来几只（给你擦的素材）

**成本**：约 60 行（权重表 + 一处取卡状态）。
**验收**：两种极端 build 各跑 200 秒，统计各阵型出场占比差异 > 30%。

### P1 · 精英 / Boss 预告条（telegraph）

**问题**：`_show_elite_warning()` 只弹一句"裂隙猎手接近"就结束（`main.gd`），
玩家不知道还有多久、没有准备时间。弹幕射击里"可预期"是底线尊重。

**方案**：精英 / Boss 触发前 3 秒，在对应屏幕边缘画倒计时条 + 低频警报音；
倒计时期间停止投放新阵型（给玩家腾出干净的登场通道）。

**成本**：约 120 行（UI + 一段预热计时）。
**验收**：倒计时期间同屏敌人数归零，`wave_probe` 加一条断言。

### P1 · 封顶精英与 Boss 的难度乘区 ⭐数值失控口

**问题**：难度曲线上仅剩的两个**无上限指数项**——
- `main.gd`: `elite_mult = 1.0 + (elite_encounter_count - 1) * 0.1`（无封顶）
- `boss.gd`: `_mult = 1.0 + boss_encounter_count * 0.2`（无封顶）

更糟的是精英的 `CHASE_SPEED = 65 * mult`（`elite.gd`）**绕过了 `_enemy_speed_cap()` 的 208 红线**，
第 20 场精英已达 188，`curve_probe` 完全不覆盖这条路径。

**方案**：精英 `min(1 + n*0.04, 2.0)`、Boss `min(1 + n*0.10, 2.5)`，
并让精英移速走 `_enemy_speed_cap()` 同一个访问口。

**成本**：约 20 行 + 在 `curve_probe` 加 3 条断言（精英移速封顶、Boss 乘区封顶）。
**验收**：`curve_probe` 全绿 + 新增断言覆盖精英/Boss 路径。

### P2 · 小行星纳入编排

**问题**：小行星血 100 / 速度 30~100 / 间隔 2~5s **全部与等级无关，且没有同屏上限**
（杂兵有 `ENEMY_SCREEN_CAP=20`，小行星只有出屏才销毁）。

**方案**：交给编排器当"场景道具"——只在退潮拍出现（作为喘息期的低压力干扰），
并加 `ASTEROID_SCREEN_CAP = 4`。顺带按章节给不同尺寸/速度档。

**成本**：约 40 行。**验收**：`wave_probe` 加同屏上限断言。

### P2 · 关卡内契约（可选支线）

**问题**：Roguelike 的"贪心 vs 安全"决策目前只存在于抽卡时刻，且抽卡有 10 秒超时兜底，
玩家其实没有真正的取舍。

**方案**：每章随机 1 条契约，例如
- 「不擦弹通过整章」→ 奖励：随机一张风格卡
- 「只用擦弹击杀 30 个」→ 奖励：永久 +3% 射速
- 「整章零受伤」→ 奖励：立即回满护盾

**成本**：约 200 行（状态机 + UI + 结算）。
**注意**：契约失败**不得有任何惩罚**，只是没拿到奖励。

### P3 · 场地事件（危险区 / 贪心点）

**问题**：9 个实体场景零 `StaticBody2D`，`main.tscn` 只有 6 个节点。
走位自由度 100% 靠躲弹幕，没有空间利用维度。

**方案**（按风险从低到高）：
1. **危险区**：周期性充能的扇形区域，进得去就别待（纯视觉 + Area2D，不遮挡弹幕）
2. **星核贪利点**：屏幕中央出现可蓄能的星核，周围 3 秒内弹幕密度 +40%，
   站上去 4 秒换一张卡——制造"要不要冒险"的决策
3. **不推荐**：实体掩体。掩体会让敌弹被遮挡，可读性直接崩掉

**成本**：单个事件约 150 行。**风险**：事件密度过高会盖掉乐句节奏，建议每章至多 1 个。

### P3 · Boss 弹幕主题随机组合

**问题**：Boss 三阶段攻击池固定，**每一局的第 15 级和上一局完全一样**。

**方案**：从 4 个主题（环雨 / 双向螺旋 / 反射激光 / 追踪雨）每战随机抽 2 个分配到三阶段。
纯配置，零新美术——调研报告 §5 补充 2 的原话。

**成本**：约 150 行。**验收**：`wave_probe` 加"同一主题不连续两战出现"断言。

### P3 · 局间 Meta（存档 + 短周期挑战）

调研报告 §5 第 5 名点名、当前完全未实现：`scripts/` 下无 `save_manager.gd`，
`leaderboard.gd` 仍是纯内存 `_entries: Array[Dictionary]`。

**方案**：`user://save.json` 存 `high_score / best_level / total_runs / meta_currency / unlocked`；
结算页 3~5 条挑战换 meta 币；**只开便利和内容，绝不开强度**
（P1 解锁了 P2 没解锁 = 天然不公平）。

**成本**：约 1.5~2.5 天。

## 4. 明确**不**推荐的方向

| 方向 | 为什么不推荐 |
|---|---|
| 判定点 12→5px | 已被 `Design_Decisions.md` 明确否决（改走"视觉放大 1.45×"）。要翻案得先推翻已固化决策 |
| 实体掩体遮挡弹幕 | 敌弹被遮挡 = 可读性崩塌，与弹幕射击的根本前提冲突 |
| 直接提高刷怪频率 / 同屏上限 | 会破坏"章节平均 ≡ 旧版速率"这条契约，且 curve_probe 第 7-8 项已锁死 |
| 退潮完全零刷怪 | 实测高等级会出现连续 16 秒空屏——那不叫喘息，叫掉线。已改为 1 只一批的涓流 |
| 联机强度型 Meta | P1/P2 起点不同，强度型解锁天然不公平 |

## 5. 验证门禁

```bash
# 波次编排门禁（25 项）
godot --headless --path . res://tests/wave_probe.tscn

# 难度曲线门禁（14 项，联机改动后必须再跑）
godot --headless --path . res://tests/curve_probe.tscn

# 联机回归门禁（36 项 = host 22 + client 14）
tests/run_probe.sh 7788
```

`wave_probe` 守的是**节奏形状**，与 `curve_probe` 守的**数值曲线**互不重叠：
有人为了让浪峰更刺激而调大 `PHASE_SHAPE` 时，`curve_probe` 会全绿（速度没越界），
但整局难度已经悄悄涨了——只有 `chapter_mean_matches_legacy` 能抓住。

它覆盖的不变量包括：章节平均 ≡ 旧版速率（误差 <0.5%）、峰谷比 ≥3.0、
平均速率随等级单调不减、闸门撑得住设计速率、所有出生点在屏外、
同屏上限不被突破、阵型不连续重复、主题倍率在安全区间、退潮涓流速率 = 设计值。
