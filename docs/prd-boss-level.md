## 4. Boss 设计概念

### 4.1 基础属性

| 属性 | 数值 | 说明 |
|------|------|------|
| 血量 | 12 | 普通敌人（2）× 6，Phase 切换阈值 6 |
| 体型 | Scale 1.8× | 视觉上明显压迫感 |
| 移动速度 Phase 1 | 2.0 | 慢速追击 |
| 移动速度 Phase 2 | 3.5 | 显著加快，接近玩家移速 |
| 触碰伤害 | 2 | 高于普通敌人的 1 点 |
| 触碰冷却 | 1.2s | 略长于普通敌人，避免连续触碰秒杀 |
| 射击冷却 Phase 1 | 2.5s | 每 2.5 秒发射 1 枚子弹 |
| 射击冷却 Phase 2 | 1.5s | 加快频率 |
| 射程 | 12.0 | 大于普通射击敌人（8.0） |
| aggro 范围 | 15.0 | 一进入房间即感知玩家 |

### 4.2 行为模式

**Phase 1（12~7 血）：橙色守卫**
- 缓慢向玩家移动（追击型，不巡逻）
- 每 2.5 秒发射 1 枚直线子弹（方向：玩家当前位置）
- 受击时白色闪烁（与普通敌人相同机制）

**Phase 2（6~1 血）：暴走模式**
- 颜色变为深红色（emission 常亮）
- 移动速度提升至 3.5
- 射击冷却缩短至 1.5s
- 触发切换时播放一次屏幕震动 + SFX 爆炸音效提示玩家

**弱点设计**
- Boss 无特殊弱点位置（当前技术框架为整体受击）
- 子弹命中任意位置均计 1 点伤害
- P1 可考虑背部弱点 × 2 伤害（后续迭代）

### 4.3 AI 逻辑伪代码

```
func _physics_process(delta):
    if health > 6:  # Phase 1
        move_speed = 2.0
        shoot_cooldown = 2.5
        _phase = 1
    else:            # Phase 2
        move_speed = 3.5
        shoot_cooldown = 1.5
        if _phase != 2:
            _enter_phase2()  # 一次性切换特效
        _phase = 2
    
    _chase_player()   # 同 enemy.gd 追击逻辑
    _try_shoot()      # 同 enemy_shooter.gd 射击逻辑
    _try_touch()      # 同 enemy.gd 触碰伤害逻辑
```

## 5. 血包道具设计

### 5.1 外观

| 元素 | 设计 |
|------|------|
| 形状 | 胶囊体（CapsuleMesh，radius 0.15，height 0.4） |
| 颜色 | 鲜红色（`#e63232`），emission 常亮，energy 1.5 |
| 动画 | 绕 Y 轴持续旋转（45°/s），轻微上下浮动（±0.1，0.8s 周期） |
| 尺寸 | Scale 0.8×（比玩家小，不挡视线） |
| 标识 | 材质颜色鲜明足够区分；不添加额外 UI 标注（保持 NES 极简风格） |

### 5.2 拾取机制

- **触碰即拾取**（Area3D，不需要按键）：玩家碰到立即生效，符合 NES 动作游戏传统
- 拾取后立即销毁（队列释放）
- 若玩家满血仍可拾取（溢出丢弃，不保留）

### 5.3 回血数值

| 血包类型 | 回复量 | 备注 |
|---------|--------|------|
| 普通血包（本次实现） | +2 HP | 玩家满血 4 HP，回复半血 |

> 玩家 `max_health = 4`（见 `player.gd:10`），+2 是半血回复，策略价值明显但不会破坏难度。

### 5.4 反馈

- 拾取时：播放 `SFX.play_ui_select()`（复用现有音效）
- 拾取时：在拾取位置生成金色伤害数字 "+2"（复用 `damage_number.tscn`，颜色改为绿色）
- HUD：现有血量条自动更新，无需额外处理

## 6. Level 04 关卡设计概念

### 6.1 基础参数

| 参数 | 值 | 说明 |
|------|----|------|
| 场景大小 | 25 × 25 单位 | 比 Level 03（20×20）稍大，给 Boss 留充足空间 |
| 关卡风格 | 最终基地·核心区 | 深色调，橙红光源，金属感障碍物 |
| 出口 | 无（击败 Boss 直接触发结算） | 无需找出口，有助于聚焦 Boss 战 |

### 6.2 敌人配置

| 位置 | 敌人类型 | 数量 | 说明 |
|------|---------|------|------|
| 入口区（0~8 单位） | 巡逻型（EnemyA/B） | 2 | 热身，玩家适应地形 |
| 中段区（8~16 单位） | 射击型（EnemyShooterA） | 1 | 给玩家压力，消耗血量 |
| 中段区 | 跳跃型（EnemyJumperA） | 1 | 干扰玩家走位 |
| Boss 房（16~25 单位） | Boss | 1 | 主战斗，大房间无障碍物（纯走位对抗） |

**总计**：4 小兵 + 1 Boss（5 个敌人）  
对比 Level 03（8 个普通敌人），小兵数量减半但 Boss 战强度大幅提升。

### 6.3 血包放置

| 编号 | 位置 | 战略用途 |
|------|------|---------|
| HP-01 | 入口区左侧角落（坐标约 -4, 0, 2） | 开局安全拾取，作为教学引导 |
| HP-02 | 中段区右侧掩体后（坐标约 4, 0, -6） | 需要绕路，有一定风险 |
| HP-03 | Boss 房入口左侧（坐标约 -3, 0, 14） | 进 Boss 前的最后补给，高价值决策点 |

### 6.4 剧情触发器文本

| 触发器 | 位置 | 文本 |
|--------|------|------|
| StoryTrigger1 | 入口（z ≈ 2） | "侦测到基地核心区——终极守卫正在等待你。" |
| StoryTrigger2 | Boss 房入口（z ≈ 15） | "警报！终极守卫现身！消灭它，任务完成！" |
| （Boss 击败后由代码触发） | — | "任务完成。终极威胁已消除。" |

### 6.5 障碍物布局

```
[入口区]
  掩体：2 个矮墙（LowWall），供小兵战斗
  HP-01 放置于左角

[中段区]
  掩体：2 个箱体（Crate），射击型敌人站于箱后
  HP-02 放置于右侧掩体后

[Boss 房]
  开阔区域，无障碍物（Boss 战需要走位空间）
  HP-03 放置于房间入口左侧
  Boss 初始位置：房间正中央偏后（z ≈ 22）
```

## 附录：技术参考

### 现有代码复用点

- `enemy_shooter.gd`：射击逻辑（`_shoot_at_target()`）可直接继承或复制至 `boss.gd`
- `enemy.gd`：追击逻辑、受击闪烁、死亡动画均可复用
- `player.gd:199`：`take_damage()` 接口，血包调用 `player.heal(amount)` 需新增 heal 方法
- `damage_number.tscn`：伤害数字，血包拾取用绿色 "+2" 显示
- `level_01.gd`：关卡基类逻辑，Level 04 继承同样结构

### 实现顺序建议（给开发代理）

1. `health_pack.gd` + `health_pack.tscn`（独立，无依赖）
2. `player.gd` 新增 `heal()` 方法
3. `boss.gd` + `boss.tscn`（依赖 enemy 系统）
4. `level_04.tscn`（依赖 Boss 和血包场景）
5. `main.gd` 扩展四关流程
6. Level 01~03 补充血包（P1-03，独立可并行）
